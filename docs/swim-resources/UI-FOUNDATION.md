# Shared admin data viewers

Admin uses a single read-only Firestore collection/document interface. `/tools/swim-resources/admin` lists registered collections; `/tools/swim-resources/admin/data/<collection>` lists documents, and `/tools/swim-resources/admin/data/<collection>/<document>` opens a document. Nested paths include athlete `bests`, import `changes`, source `checks`/`revisions`, and provenance `events`/`disagreements`. Collection columns, typed filter fields, and subcollection links live in `src/features/swim-resources/lib/domain/data-viewer.ts`. Adding a registry entry reuses the same UI; it does not change Firestore permissions.

Navigation, tables, forms, readable field/value details, and expandable raw JSON use system fonts, thin borders, and existing light/dark tokens. The schema diagram at `/tools/swim-resources/admin/map` is the only admin map. There are no geographic maps, pool illustrations, charts, colored tiers, resizable panes, or admin editing dialogs. Styles are scoped to `.admin-simple`; public pages retain their existing presentation.

Reads use the authenticated Firebase client, require a verified Velocity coach, and remain subject to existing Firestore rules. Queries read at most 100 documents per page, use cursor pagination, and support one typed equality filter or an exact document-ID lookup. Filters live in the URL; changing the database filter starts a new first page. Search is explicitly limited to loaded rows. A full final page can be followed by an empty page; Previous returns to the last results. Refresh reloads the current filter from its first page.

Document viewers show stored fields, not computed coaching interpretations. Nested objects and arrays expand on demand. Timestamps preserve seconds/nanoseconds, coordinates display latitude/longitude, references display their paths, and binary data displays base64. The raw JSON is a readable normalized representation, not a Firestore backup/export format. Missing stored fields remain missing.

Existing admin routes redirect to the associated stored collection; Roster and Athletes share `athletes`, the old Records route opens `swims`, and Analysis shows saved `analytics_snapshots`. Athlete-specific links become document selection or an `athleteId` filter where relevant. Other legacy view/layout parameters are discarded. `/tools/swim-resources/attendance/admin` redirects to the stored attendance collection; the separate `/tools/swim-resources/attendance` app remains available.

Goals and Film Sessions are outside the active scope. They and the stored `records` collection are absent from the collection registry, schema map, relationships and maintenance filters. Direct viewer paths are not registered, the old Goals page is removed, and rules deny their client reads/writes. Team records will be calculated from `swims`; importing or reversing a race refreshes athlete best times without creating stored record boards. Historical archives remain unchanged.

Import is the action-bearing exception. Its plain tables and controls retain prepared batches, preview, selected apply, review acknowledgments, private source references, receipts, projection recovery, guarded reversal, and saved HTML inspection. No changes are selected automatically. Persistence writes retain canonicalization and now record private origins/evidence; data viewers never call write services.

Verification uses synthetic fixtures and demo emulators for authorization, bounded queries, missing documents, nested fields/subcollections, pagination/filter changes, redirects, light/dark/mobile presentation, and Import apply/recovery/reversal. Never verify edits with dummy records in the live coaching project.

## Data structure map

`/tools/swim-resources/admin/map` provides a read-only diagram of all registered root collections and registered subcollections, including bests, receipts, check history, revisions, evidence events and disagreements. Select a node or use the collection selector to see direct relationships; enable the overview to show the entire catalog. Ownership arrows are optional, while the text relationship table always includes ownership. Keyboard users can select diagram nodes with Enter or Space, or use the selector and relationship buttons. The diagram scrolls horizontally on mobile.

`src/features/swim-resources/lib/domain/data-map.ts` describes purposes, public/private read boundaries, reference fields, containment, derived projections, workflow connections and simplification review candidates. Coverage tests require every viewer registry entry to have a description. This is a declared schema map, not a live field/count inventory or a database integrity check. Optional and legacy links are identified; no database reads or writes occur on the map page. Collection links open the authenticated viewers; subcollection links open the parent collection so a real document can be selected.

Review candidates cover embedded meet venue/attachment data, directory identity, typed attendance, derived performance data and import retention. Legacy results are excluded from the fresh model. Review candidates do not authorize deletion or migration.

## Fresh evidence views

The header identifies the project/database. Fresh Import is disabled in the original database. Business document pages show private field coverage, source/revision/check links, accepted verification dates separately from actual fact-change dates, attention reasons and history. Archived revisions download only through authenticated Storage blob reads, with hash verification. Collection filters include stored attention flags; a separately labeled attention checkbox computes due/uncovered fields only within loaded rows. The data map includes the private Evidence group and its relationships.

## Maintenance

`/tools/swim-resources/admin/maintenance` reuses authenticated, allowlisted collection reads for `record_provenance` and `sources`. Each page reads at most 100 documents with cursor pagination. The record-collection selector applies one Firestore equality filter. Attention type and search inspect only the loaded page; an empty page of attention results does not claim that the database has no issues. Changing collection, view or attention type resets pagination; search preserves the current page. Refresh reloads the current cursor and recomputes due dates.

The plain table separates successful verification, fact changes and next check dates. It shows overdue external field checks, uncovered required fields, retrieval failures, competing claims and open review questions. Manual declarations, disabled sources, retired records and clean derived/audit records do not receive an invented external checking schedule. Source retrieval timestamps or captures do not count as successful scope verification; a missing source-level verification date does not erase accepted field evidence on individual records. UTC dates use readable lines, with exact timestamps retained in semantic time elements and titles. The table has keyboard focus and horizontal scrolling on narrow screens. Links open records, provenance, exact captures, checks, disagreements and the existing reviewed Import workflow; the queue itself performs no writes.

Review questions are private annotations on record provenance, distinct from competing factual claims. They keep exact source/revision/check references and affected field names without accepting a proposed value. Success checks and reviewed imports preserve open questions; resolution is explicit and retained in immutable history. Reversal preserves independently added questions. No geographic map, scheduler or embedded AI is introduced here.
