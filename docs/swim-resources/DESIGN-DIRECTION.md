# Information platform direction

The current priority is development speed through a shared, plain admin data viewer. Read-only collections and document details replace bespoke dashboards, pool illustrations, maps, charts, and editors. Import retains its reviewed write workflow. See [the shared interface](UI-FOUNDATION.md).

The next platform phase connects teams, contacts, venues, meets, documents, and sources with stable identities. Collection configuration should reuse the viewer; relationships and source-backed maintenance should live in domain services and dedicated agent tools rather than page-specific presentation.

Every maintained fact needs evidence, successful-check timestamps, and visible unresolved conflicts. Keep meet venues distinct from club home locations, revised packets linked to their predecessors, and mailbox-derived evidence private. Failed or partial collection preserves prior facts and the last successful complete checkpoint.

Routine verified directory updates and document additions may eventually apply automatically under an explicit maintenance policy. Conflicting facts and consequential meet changes require coach attention. The current Import workflow still requires selected coach review; this UI simplification does not enable new automatic writes or schedules.

A future national map and grouped contact directory can be optional views of the same connected data. Geographic coverage must distinguish sources checked with no results from regions not checked. Hosted upkeep needs independently configured source access and credentials. Existing local collection scheduling remains gated by the pilot acceptance criteria in [COLLECTION-PILOT.md](COLLECTION-PILOT.md).
